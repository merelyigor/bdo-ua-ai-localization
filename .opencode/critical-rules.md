# Критичні заборони · bdo-ua-ai-localization

- `git commit`/`push`/force-операції · тільки з явним одноразовим дозволом власника.
- У commit message і у файлах ЗАБОРОНЕНА атрибуція AI-інструмента: ніякого
  `Co-Authored-By` з моделлю, ніякого «Generated with …». Автор · власник. Це
  сильніше за дефолтний шаблон будь-якого інструмента.
- Ключі API живуть у `.env` і ніде більше. Не виводити їх у відповідь, лог чи код;
  `.env` не комітити. Це ПУБЛІЧНИЙ репозиторій: історія незнищенна без force-push,
  тому сюди не потрапляють ні секрети, ні персональні дані власника, ні опис його
  інфраструктури понад те, що вже є в дефолтах скриптів.
- Запобіжник у клоні вмикається один раз: `git config core.hooksPath .githooks`.
- Прод-запис (`--env prod`) · лише з явним дозволом на конкретний прогін. За
  замовчуванням цілимось у local.
- Ідентичність рядка = `source_language + key0 + record_id + key1`. Не змінювати,
  не вигадувати, не переставляти. `identity_hash` приходить з API і повертається
  без змін.
- PA markup (`<PAGraphic>…</PAGraphic>` тощо), placeholders (`%1`, `%2`) і теґи в
  квадратних дужках копіюються байт у байт.
- Текстові шари розділені (English / Ukrainian manual / machine / reference).
  Ручні переклади, ревізії й рішення модераторів не перезаписувати ніколи.
- Підстановка згадок у LOC · лише для предметів; ніколи для NPC, локацій чи лору:
  гра вилітає.
- Видимий користувачу текст · українською, без тире «—», лише `·` або дефіс.
  Це найчастіша причина, з якої QA завертає готовий рядок.
- Жодних латинських гомогліфів у кирилиці й жодної російської у видимому тексті.
- Модель субагента · тільки GGUF зі списку `validate-translation-agents.sh`. MLX
  заборонений: його runner мовчки ігнорує constrained decoding, і схема пачки
  перестає діяти.
- Субагенти під схемою не мають інструментів ЖОДНИХ, включно з `read`: виклик
  інструмента знімає constrained decoding. Payload передається текстом у промпті.
- Результат прогону субагентів перевіряти в базі OpenCode через `./verify-run.sh`,
  а не зі скріншотів чи самозвіту агента: модель уже помилялась щодо провайдера й
  не помічала помилку плагіна.
- Не запускати одночасно OpenCode-флоу й автономний `translate-patch.sh`: вони
  ділять одну модель Ollama, і паралельні запити псують один одного.
- `output/`, `state/`, `state-auto/` · робочий стан, не артефакти для коміту.
  Курсори прогонів у `state-auto/` не видаляти: там збережені позиції вибірок.

## Помилки, які тут уже робили

- Курсор рухали одразу після fetch · Ctrl+C посеред пачки тихо викидав її з
  черги. Тепер позиція зберігається лише після завершення пачки.
- Перемкнули модель у проєктному конфізі, але не оголосили її провайдеру в
  користувацькому конфізі OpenCode · дочірні сесії створювались порожніми, нуль
  токенів і жодної помилки в UI. Перевірка: `./sync-opencode-models.sh`.
- Модель бенчмаркали без прогріву · перший запит містить завантаження ваг і
  занижує швидкість на 10-25%.
- Основна модель у звіті збрехала про провайдера субагентів і не помітила червону
  помилку плагіна. Джерело правди · база OpenCode, не самозвіт.
