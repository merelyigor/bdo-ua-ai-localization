# Запис ШІ-перекладів через API

`cli/write/write-translations.sh` записує результат у машинний шар з тілом
`layer=machine` і `mode=direct`.

Перед записом скрипт мусить викликати `GET /me`. Прямий машинний запис доступний,
лише якщо одночасно виконано все нижче (звірено з живим PROD API 2026-09-04):

- роль власника ключа: `admin` або `super_admin`;
- у `effective_abilities` є `translations:write-machine`;
- у запиті задано непорожні `provider` і `model`;
- кожен рядок пройшов `POST /translations/validate`.

Такий запис не обходить перевірку: сервер зберігає `validation_result`, походження
`ai_api`, provider, model, версію промпта та ревізію. Він не створює пропозицію,
бо це саме машинний шар.

Джерело правди про дозвіл · `GET /me` → `writes.channels`: СПИСОК обʼєктів
`{layer, mode, allowed, result}`, а не мапа за назвою каналу. Форму треба читати
саме так: 2026-08-29 вигадана мапа заблокувала кожен коміт помилкою
`api_write_failed`, і пачка з 50 готових рядків стала в `committing` (D33).

Для інших ролей дозволений лише аудитований потік `layer=manual` +
`mode=proposal`. Він створює пропозицію; модератор і вищі ролі можуть схвалити її
за правилами модерації. `manual + direct` і `machine + proposal` сервер відхиляє.

Якщо `/me` не дає машинну здатність, не намагайтеся обійти обмеження зміною поля
`layer`. Зупиніть автоматичний запис або використайте ключ, виданий для admin чи
super_admin.
