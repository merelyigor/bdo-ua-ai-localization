Набір інструментів для української локалізації **Black Desert Online** у
проєкті [BDO UA Translate](https://bdo-ua.com.ua). Це клієнт Agent API, а не
сервер: база рядків, глосарій, модерація й адмінка живуть на сайті.

Усе керування · у браузері. Значок `BDO.app` (або одна команда) піднімає
локальну сторінку: підключення, вибір моделі, старт прогону, прогін наживо,
черга до людини й історія сесій. Порядок кроків тримає Python-код, мовну роботу
виконують моделі (OpenCode Go, сумісний з OpenAI сервіс або локальні Ollama/oMLX), а перед
записом кожен рядок проходить механічні перевірки й `validate` сайту.
Наступник PHP-проєкту `bdo-ua-ai-localization`.

## Швидкий старт

Потрібні [`uv`](https://docs.astral.sh/uv/) і ключ Agent API з вашого кабінету
на сайті; Python потрібної версії `uv` поставить сам. Перевірено на macOS.

```bash
git clone https://github.com/merelyigor/bdo-ua-ai-localization.git
cd bdo-ua-ai-localization
uv sync
uv run bdo web start
```

1. Під час першого запуску `.env` створюється сам (середовище PROD), а
   браузер відкриває екран «підключення».
2. Ключ Agent API: кабінет
   [`bdo-ua.com.ua/admin/profile`](https://bdo-ua.com.ua/admin/profile) →
   «API доступ» → «Показати» → скопіюйте ключ (починається з `bdo_`) і
   вставте на екрані «підключення». Там же, за потреби, · адреси Ollama/oMLX.
3. На екрані «моделі» оберіть модель, на «Старті» · патч і розмір пачки, далі
   «почати прогін». Спершу · dry-run без запису.

На macOS є значок: `uv run bdo app build` збирає `BDO.app` у корені
репозиторію; перетягніть його в Dock, не переміщуючи з кореня. Клік піднімає
сервер і відкриває сторінку, «Завершити» · зупиняє.

## Як працює конвеєр

Одна пачка рядків проходить фіксований порядок кроків; кожен крок читає вхід зі
SQLite, робить свою роботу й записує результат, перш ніж перейти далі:

```text
рядки з API → памʼять перекладів → термінолог → перекладач → механічні перевірки
  → контроль якості → ремонт (за потреби) → суддя → імена → validate сайту → запис
```

| Роль | Що робить |
|---|---|
| `translation-terminology` | зіставляє терміни пачки з глосарієм і пропонує відповідник для нових |
| `translation-worker` | перекладає рядки |
| `translation-qa` | перевіряє переклад і позначає дефекти |
| `translation-repair` | виправляє рядки, які відхилили перевірки |
| `translation-judge` | обирає маршрут готового рядка (запис чи модерація) з оцінкою впевненості |
| `translation-names` | вказує, де підставити затверджені назви; текст міняє код |

Роль отримує мінімальний payload і відповідає JSON за схемою
([`roles/schema/`](roles/schema/)). Модель не керує порядком кроків, не має
інструментів і не бачить хешів рядків: замість них · короткі `id` виду `r1`.
Механічний дефект (placeholders, розмітка, `{BDO_NL}`, довжина) сильніший за
вирок моделі. Проблемний рядок іде в модерацію, збій мережі · у карантин;
нічого не пропускається мовчки.

## Режими й канали запису

| Режим | Що бере | Куди пише |
|---|---|---|
| `patch` | нові й змінені рядки патча | `machine` · звичайний автоматичний шар |
| `improve` | уже перекладені рядки для покращення | `machine` |
| `manual` | ручний шар із серверними дозволами | `manual` |
| `proposals` | відкриті пропозиції з черги до людини, повторно | `machine`, якщо рядок чистий (пропозиція відхиляється); інакше нова пропозиція замість старої |

Куди йде запис, видно на «Старті»: картка «Куди пишемо» перемикає DEV/PROD, а
перехід на PROD потребує підтвердження. Середовище DEV потрібне лише для розробки.

## Екрани

| Група | Шлях і назва | Що показує |
|---|---|---|
| Робота | `/run` · прогін | стан сесії й пачки, події та виклики ролей наживо, рядки й причини відмов |
| Робота | `/review` · черга до людини | пропозиції перекладу, пошук і схвалення або відхилення |
| Робота | `/sessions` · сесії роботи | історію сесій, пачок і їхні причини завершення |
| Робота | `/start` · почати прогін | середовище, режим, патч, розмір і кількість пачок, dry-run або запис |
| Робота | `/models` · моделі | провайдери, активну модель, роздуми на роль, smoke-перевірки й ліміти Go |
| Діагностика | `/setup` · підключення | ключі BDO API, адреси й ключ локальних моделей |
| Діагностика | `/status` · стан | середовище, хост API, стан ключа, версію й перевірку редагування логів |
| Діагностика | `/api` · API | `/me`, рядки, контекст, памʼять, validate та помилки API |
| Діагностика | `/calls` · виклики | журнал викликів моделей; кожен рядок веде до деталей |
| Діагностика | `/call?id=<id>` · деталі виклику | запит, роздуми й відповідь моделі, розібраний JSON та replay |
| Діагностика | `/quality` · якість | механічні перевірки на прикладах зламаного тексту |
| Діагностика | `/queue` · карантин і запис | відкладені рядки, карантин, модерацію, записи й ключі повтору |
| Діагностика | `/stats` · статистика | час ролей і пачок, порівняння з попередником та A/B replay |
| Діагностика | `/compare` · порівняти моделі | ті самі рядки на двох моделях поруч |

`/` веде на `/setup`, поки не задано ключ BDO API активного середовища, далі ·
на `/run`.

## Дані й безпека

- Ключі живуть лише в локальному `.env` (під `.gitignore`); на сторінку
  їхні значення не повертаються. Шаблон змінних · [`.env.example`](.env.example).
- Увесь стан · один файл `.bdo/bdo.sqlite`; там же журнал сервера й знімки
  звірки. Тека `.bdo/` у git не потрапляє.
- Безкоштовним віддаленим моделям іде лише текст рядків гри, ніколи ключі чи
  журнали. Правила публічного репозиторію · [`docs/SECURITY.md`](docs/SECURITY.md).

## Для розробника

Код пишуть агенти за планами; правила · [`AGENTS.md`](AGENTS.md) (канон) і
побайтова копія `CLAUDE.md`, деталі · [`docs/RULES_REFERENCE.md`](docs/RULES_REFERENCE.md).
Автотестів немає: кожен крок перевіряється у справжньому браузері на живих
даних DEV, знімки · у `.bdo/playwright/`.

```bash
git config core.hooksPath .githooks   # формат комітів, секрети, особисті дані
uv run bdo gate                       # secrets, docs, lint, types · за секунди
uv run bdo web start                  # сторінка; друкує URL
uv run bdo version                    # версія пакета = рядок 1 коміту
```

Промпт для сесії агента-розробника:

```text
Прочитай AGENTS.md, docs/PLANNING.md і docs/plans/README.md. Візьми активний
план, прочитай його заголовок і «Instructions for the executor», почни з
першого кроку зі статусом не done. Працюй лише за планом. Наприкінці · звіт
за форматом AGENTS.md.
```

| Шлях | Що |
|---|---|
| `src/bdo_translate/` | код: конвеєр, клієнт API, моделі, перевірки, вебсторінка, `bdo` CLI |
| `roles/`, `roles/schema/` | промпти ролей і JSON-схеми відповідей |
| `config/roles.json`, `config/modes.json` | параметри ролей; режими прогону й канали запису |
| `docs/`, `docs/plans/` | довідник, рішення, архітектура, плани й реєстри |
| `reference/` | карта попередника (read-only), форми payload, знімки старого інтерфейсу |
| `scripts/executor/` | Бригада (виконавці й помічники) ([`docs/EXECUTOR_HARNESS.md`](docs/EXECUTOR_HARNESS.md)) |
| `BDO.app` | зібраний значок macOS, переносний |
