Локальна програма, яка перекладає тексти **Black Desert Online** українською
для спільноти [BDO UA Translate](https://bdo-ua.com.ua). Вона бере рядки гри
через Agent API сайту, перекладає їх обраною моделлю ШІ, перевіряє кожен рядок
кодом і лише тоді записує переклад на сайт. Сумнівне не пишеться: воно йде в
чергу до людини.

Усе керування відбувається в браузері, команди складати не треба. Сайт тримає
базу рядків, глосарій, модерацію й адмінку, а програма лише клієнт до нього.

## Чому саме так

- **Порядок кроків тримає код, а не модель.** Модель виконує лише мовну роботу
  однієї ролі. Вона не має інструментів, не керує процесом і відповідає JSON за
  жорсткою схемою, тож «творчо» зламати конвеєр не може.
- **Механічні перевірки сильніші за думку моделі.** Навіть коли модель каже
  «добре», зламаний placeholder, розмітка чи перенос рядка не пройдуть до запису.
- **Нічого не зникає мовчки.** Проблемний рядок іде в чергу до людини, а збій
  мережі чи моделі відкладає його для повтору. Кожна відмова має машиночитану
  причину, яку видно на екрані.
- **Дані гри в безпеці.** Модель не бачить ідентифікаторів рядків (замість
  хешів вона отримує короткі `r1`, `r2`), і їй іде лише мінімальний текст пачки.
  Ключі й журнали ніколи не потрапляють до моделі.
- **Будь-яка модель.** Хмарна OpenCode Go, будь-який сервіс, сумісний з OpenAI,
  або локальні Ollama, oMLX і llama-swap на вашому залізі. Модель обирається
  на екрані без правки коду. Під час вибору програма робить пробний виклик
  моделі, а перед першою пачкою перевіряє, чи модель досі є в каталозі джерела.
- **Видно все.** Прогін наживо, кожен виклик моделі з запитом, роздумами й
  відповіддю, статистика часу, порівняння двох моделей на тих самих рядках.
- **Переклад підписаний.** Кожен запис несе модель, провайдера й версію
  програми, тож пізніше можна покращити лише те, що перекладала старша версія.

## Як перекладається пачка

Пачка рядків проходить фіксований шлях. Кожен крок читає вхід із локальної
бази SQLite, робить свою роботу й записує результат, перш ніж іде далі. Стан
однієї пачки не змішується з іншою, а черга рядків рухається далі лише після
того, як пачка завершилась.

```text
рядки з API → памʼять перекладів → термінолог → перекладач → механічні перевірки
  → контроль якості → ремонт (за потреби) → суддя → назви → validate сайту → запис
```

### Ролі моделі

| Роль | Що робить |
|---|---|
| Термінолог (`translation-terminology`) | зіставляє терміни пачки з глосарієм сайту й пропонує відповідник для нових |
| Перекладач (`translation-worker`) | перекладає рядки з урахуванням глосарія, памʼяті перекладів і контексту гри |
| Контроль якості (`translation-qa`) | читає переклад і позначає дефекти: сенс, стиль, терміни |
| Ремонт (`translation-repair`) | виправляє лише ті рядки, які відхилили перевірки, і лише названі дефекти |
| Суддя (`translation-judge`) | вирішує долю готового рядка: запис чи черга до людини, з оцінкою впевненості |
| Назви (`translation-names`) | вказує, де стоять назви гри; підставляє затверджені відповідники вже код |
| Перевірка (`translation-smoke`) | короткий виклик без рядків гри: перевіряє, що канал до моделі живий і модель тримає схему відповіді |

Промпти ролей лежать у [`roles/`](roles/), схеми відповідей · у
[`roles/schema/`](roles/schema/). Кожен промпт самодостатній і розрахований
на слабшу модель, тому працює й на локальних.

### Механічні перевірки

Кодом, без моделі, перевіряється кожен рядок:

- placeholders, PA-розмітка, переноси `{BDO_NL}` і структура переліків;
- довжина відносно обмежень рядка;
- латиниця й цифри, схожі на кирилицю (гомогліфи), та чужі писемності;
- русизми й кальки з підказкою правильного слова;
- регістр людських відповідників глосарія;
- вигадані дужкові токени, яких немає в оригіналі;
- і наостанок · `validate` на сайті.

Морфологія української (леми, відмінки) у конвеєрі **не** перевіряється.
`quality/morph.py` працює лише як тіньова діагностика на екрані «Якість»: вона
показує, де правило точного збігу розходиться з пошуком за лемами, але не
блокує запис і не входить у механічні дефекти.

Зациклену відповідь моделі програма ловить за повторами фрагментів, а не
обрізанням: обсяг відповіді й роздумів моделі не обмежується.

## Режими прогону

| Режим | Область | Що бере | Куди пише |
|---|---|---|---|
| патч (`patch`) | патч | нові рядки патча | ШІ-шар (`machine`) |
| актуализація (`refresh`) | патч | рядки ШІ-шару, де змінився англійський оригінал | ШІ-шар |
| покращення (`improve`) | корпус | увесь ШІ-шар, який ще не покращувала **ця** програма (фільтр `machine_client_name_not=bdo-ua-translate-python`) | ШІ-шар |
| ручний (`manual`) | корпус | рядки без ручного шару | ручний шар (`manual`), **пропозицією** |
| пропозиції (`proposals`) | черга | відкриті пропозиції з черги до людини, повторно | ШІ-шар, якщо рядок тепер чистий; інакше нова пропозиція замість старої |

«Область» — межа вибірки: **патч** бере рядки з патча (активного за
замовчуванням), **корпус** — з усього корпусу гри, **черга** — не рядки, а
відкриті пропозиції Agent API. Режим `manual` пише **пропозицією**: канал
`manual` у [`config/modes.json`](config/modes.json) має `mode: proposal`, тому
рядок іде в чергу до людини, а не просто в шар.

Кожен режим можна спершу запустити як **dry-run** (тестовий прогін): програма
пройде весь шлях, але нічого не запише. Це не окремий режим прогону, а прапорець
запуску на екрані «почати прогін».

## Швидкий старт

### Що потрібно

1. [`uv`](https://docs.astral.sh/uv/). Python потрібної версії (3.13+) `uv`
   поставить сам.
2. **Ключ Agent API.** Його отримує будь-який користувач сайту: напишіть
   адміністратору або в [Discord спільноти](https://discord.gg/SJEP23tsUv)
   (посилання є й на [сайті](https://bdo-ua.com.ua)). Ключ потім видно в
   кабінеті: [`bdo-ua.com.ua/admin/profile`](https://bdo-ua.com.ua/admin/profile)
   → «API доступ» → «Показати» (починається з `bdo_`).
3. **Модель.** Одне з: ключ OpenCode Go, адреса й ключ
   сервісу, сумісного з OpenAI, або локальні Ollama, oMLX чи llama-swap.
   Повний прогін пачки на локальній моделі перевірено на oMLX (Apple Silicon):
   одна пачка з 5 рядків пройшла всі ролі приблизно за 6 хвилин. Ollama й
   llama-swap працюють через той самий код, але повним прогоном ще не перевірені.

### Запуск

```bash
git clone https://github.com/merelyigor/bdo-ua-ai-localization.git
cd bdo-ua-ai-localization
uv sync
uv run bdo web start
```

1. Під час першого запуску файл `.env` створюється сам, а браузер відкриває
   екран «підключення». Вставте туди ключ Agent API і, за потреби, адреси
   локальних моделей.
2. На екрані «моделі» додайте ключ моделі й оберіть активну модель. Там же
   видно ліміти підписки й рівень роздумів для кожної ролі.
3. На «Старті» оберіть режим, патч і розмір пачки й натисніть «почати прогін».
   **Спершу dry-run:** програма одразу працює з робочим сайтом (PROD), і
   запис без dry-run потрапить у справжній переклад.

Якщо прогін завершився помилкою моделі або порожньою вибіркою, на екрані
«прогін» зʼявиться кнопка «повторити відкладені». Вона створить нову сесію з
придатних рядків того самого середовища й режиму. Безкоштовні моделі краще
пускати пачками по 5–15 рядків: велика відповідь може обірватися з
`done_reason=length`. Блок «Вибірка рядків» пояснює, скільки рядків API
повернув і чому частину відсіяно, без показу текстів і хешів.

Сторінка живе на `http://127.0.0.1:7660/` (порт змінює `BDO_WEB_PORT` у `.env`).
Зупинити сервер · `uv run bdo web stop`.

## Як перевірити, що все працює

Три перевірки, від найдешевшої до найдорожчої. Кожна має закінчитися кодом 0
або зрозумілим результатом на екрані.

1. **Версія пакета.** `uv run bdo version` друкує поточну версію пакета.
   Вона має збігатися з версією в `pyproject.toml` і `uv.lock`.
2. **Статичні перевірки.** `uv run bdo gate` перевіряє секрети, посилання в
   документації, лінтер і типи. Успіх · повідомлення про зелений gate і код 0.
   Окремо можна запустити профіль: `uv run bdo gate secrets|docs|lint|types`.
3. **Живий сервер.** Після `uv run bdo web start` відкрийте
   `http://127.0.0.1:<порт>/health`. Очікується JSON:
   `{"ok":true,"version":"<версія>","env":"DEV|PROD","busy":false}`. Поле `busy`
   дорівнює `true`, поки йде прогін. Порт за замовчуванням `7660`.

Перший запуск без ключа створює `.env` сам і відкриває екран «підключення»:
вставте ключ Agent API, оберіть модель на екрані «моделі» і зробіть тестовий
прогін (dry-run) на DEV.

### Значок для macOS

Зібраний значок `BDO.app` лежить у корені репозиторію; перетягніть його в Dock,
не переміщуючи з кореня. Клік піднімає сервер і відкриває вікно з адресою,
версією й середовищем та кнопками «Відкрити в браузері», «Перезапустити сервер»
і «Сховати». Вкладка браузера сама не відкривається. Перезібрати значок ·
`uv run bdo app build`.

### Платформи

Перевірено на macOS. Windows і Linux **не перевірено**; підтримку додамо, коли
виникне потреба. Допомога з Windows вітається, але лише через pull request, який
пройде перевірку.

| Діагностика | `/setup` · підключення | ключі Agent API, адреси й ключі локальних моделей |
| Діагностика | `/status` · стан | середовище, хост API, стан ключа, версію |

## Дані й безпека

- Ключі живуть лише в локальному `.env` (під `.gitignore`); сторінка їхніх
  значень не показує. Шаблон змінних · [`.env.example`](.env.example).
- Увесь стан · один файл `.bdo/bdo.sqlite`; там же журнал сервера. Тека `.bdo/`
  у git не потрапляє.
- Безкоштовним віддаленим моделям іде лише текст рядків гри, ніколи ключі чи
  журнали. Правила публічного репозиторію · [`docs/SECURITY.md`](docs/SECURITY.md).

## Для розробника

Код пишуть агенти за планами; короткі факти проєкту · [`AGENTS.md`](AGENTS.md)
(єдиний канон; `CLAUDE.md` лише імпортує його рядком `@AGENTS.md`), деталі · документи в [`docs/`](docs/).
Автотестів немає: кожен крок перевіряється у справжньому браузері на живих
даних середовища розробки (DEV). Pull request приймається після такої ж
перевірки й зеленого `gate`.

```bash
git config core.hooksPath .githooks   # формат комітів, секрети, особисті дані
uv run bdo gate                       # secrets, docs, lint, types · за секунди
uv run bdo web restart                # перезапуск сервера без нової вкладки
uv run bdo version                    # версія пакета = рядок 1 коміту
```

| Шлях | Що |
|---|---|
| `src/bdo_translate/` | код: конвеєр, клієнт API, моделі, перевірки, вебсторінка, `bdo` CLI |
| `roles/`, `roles/schema/` | промпти ролей і JSON-схеми відповідей |
| `config/roles.json`, `config/modes.json` | параметри ролей; режими прогону й канали запису |
| `docs/`, `plans/` | API, безпека, архітектура, рішення, плани й реєстр планів |
| `reference/` | карта попередника, форми payload, знімки старого інтерфейсу |
| `AGENTS.md` | короткі факти проєкту для агентів: гейти, git, небезпечні місця |
| `BDO.app` | зібраний значок macOS, переносний |
