# Git і повідомлення комітів

## Зміна стану Git

- Додавай лише власні файли поіменно: `git add <шлях>`. Заборонені `git add .`, `git add -A`, `git commit -a`, `--no-verify`, `git push --force`, теги, `git reset --hard`, `git clean -fd` і `git checkout -- <файл>` із чужими змінами.
- Звіряй `git status --short` до роботи й перед публікацією. Незакомічені зміни поза визначеним scope не змінюй.
- Push і створення тегів виконує лише власник. Нове переписування історії Git потребує окремого рішення власника.
- Видалення файлів і даних `.bdo/` дозволене лише за окремим дозволом власника на цю дію. Кнопка «Архівувати карантин» є дозволеним винятком: вона позначає записи як `archived`, а не видаляє їх.
- Локальні хуки `.githooks/pre-commit`, `.githooks/commit-msg` і `.githooks/pre-push`
  — це шебанги, що викликають `uv run --quiet bdo hook pre-commit`,
  `uv run --quiet bdo hook commit-msg` і `uv run --quiet bdo hook pre-push`.
  Той самий код доступний руками: `uv run bdo hook pre-commit`,
  `uv run bdo hook commit-msg <файл-повідомлення>`,
  `uv run bdo hook pre-push`. `commit-msg` без шляху до файла повідомлення
  повертає код 2.

## Формат коміту

Повідомлення пишеться у файл і передається як `git commit -F <файл> -- <шляхи>`: кілька `-m` створюють зайві порожні рядки. Перелік `-- <шляхи>` має збігатися з блоком `Файли:`.

```text
Версія: 0.7.1

P08: модуль статистики рахує час за роллю з таблиці calls. Перевірено:
uv run bdo gate, код 0.

Файли:
pyproject.toml
src/bdo_translate/__init__.py
uv.lock
src/bdo_translate/pipeline/stats.py
```

- Перший рядок — рівно `Версія: X.Y.Z`, далі порожній рядок.
- Один абзац українською: зміна, причина й перевірка з командою та кодом виходу. Перше речення починається з `P0N:`, `Плани:`, `Правила:` або `Задача:`.
- Далі порожній рядок і `Файли:`, по одному шляху на рядок без порожніх рядків. Зазначай усі змінені й видалені шляхи.
- Не використовуй Markdown і не додавай AI-атрибуцію (D-42): заборонені `Co-Authored-By`, `Generated with` та 🤖. `.claude/settings.json` зберігає порожню `attribution`.

## Версія

Версія коміту є версією продукту: узгоджені значення в `pyproject.toml`, `src/bdo_translate/__init__.py` та `uv.lock` після `uv sync`; `uv run bdo version` друкує її. Коміт закриття плану P0N має версію `0.N.0`; інші коміти підвищують PATCH на одиницю від HEAD. PATCH не має стелі. Версія не змінюється для amend, який не змінює файлів. Перед кожним комітом звір `git log -1 --format=%B` і `uv run bdo version`, бо інша сесія могла оновити HEAD.
