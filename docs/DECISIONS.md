# Рішення, які вже ухвалені

Реєстр технічних рішень проєкту. Агент-розробник їх НЕ переобирає: якщо крок
плану суперечить рішенню тут, крок помилковий і це `blocked`. Змінює рішення
лише власник; зміна · новий рядок зі статусом `замінено` і посиланням.

Формат: `D-NN · рішення · чому · як це видно`.

## Принципи (рішення власника 2026-09-25)

- **D-00a · Лише Python.** У репозиторії немає bash-, PHP- чи інших скриптів.
  Усе службове (gate, старт і стоп сторінки) · команди `bdo` у пакеті
  `bdo_translate`. Файл `*.sh` у репозиторії · порушення, яке ловить `bdo gate lint`.
- **D-00b · Автотестів немає.** У попередника 103 bash-тести коштували час, а
  баги все одно пролазили. Теки `tests/`, файлів `test_*.py`, `conftest.py`,
  `pytest` у проєкті немає. Приймання · лише браузер (D-33).
- **D-00c · Мінімум власної логіки.** Протоколи, повтори, сховище, CLI,
  налаштування, валідація, класи писемності · бібліотеками (D-35). Власний
  код лише там, де правило є предметною знанням проєкту: порядок кроків,
  маршрути рядка, механічні перевірки перекладу, `RowAlias`, `RepeatWatch`.
- **D-00d · Стан · один файл SQLite, без JSONL і файлів пачок** (D-05).

## Стек

- **D-01 · Python ≥ 3.13, керує `uv`.** На машині власника Python 3.14.7 і
  `uv 0.11.3` (перевірено 2026-09-25). `uv sync` створює `.venv`, `uv run`
  запускає все; `pip`, `poetry`, `conda` не вживаються.
- **D-02 · src-layout, пакет `bdo_translate`, CLI `bdo` через `typer`.**
  CLI лише для розробника: `version`, `env`, `gate`, `web serve|start|stop|status`;
  затверджені плани додають `hook` (P10 фаза 3) і `bdo` без аргументів (P11
  крок 6.1). Решта дій · кнопки сторінки (D-36). Нові залежності не додаються без рядка
  в цьому файлі й дозволу власника.
- **D-03 · HTTP до Agent API · `httpx.AsyncClient`; повтори · `tenacity`.**
  Один клієнт на процес, таймаути явні. Моделі · через офіційні SDK (D-11).
- **D-04 · Контракти даних · `pydantic` v2; вихід моделі валідується
  `jsonschema` (Draft 2020-12) проти схеми ролі ПІСЛЯ підміни alias.** Та сама
  схема йде моделі як constrained decoding.
- **D-05 · Стан · один файл `.bdo/bdo.sqlite` через `sqlmodel`** (таблиці ·
  класи Python у `store/models.py`, без ручного SQL). Запит і відповідь
  кожного виклику моделі, payload ролей, вироки, записи · колонки таблиць, а
  не файли. JSONL немає. Версія схеми · `PRAGMA user_version`; нова таблиця
  створюється `SQLModel.metadata.create_all`, нова колонка · рядок
  `ALTER TABLE … ADD COLUMN` у `store/db.py:UPGRADES`. Схема лише
  розширюється; видалення чи перейменування колонки · рішення власника.
- **D-05a · Усі локальні дані · в одній теці `.bdo/`** під `.gitignore`:
  `bdo.sqlite`, `web.log`, `web.pid`, `web.started`, `playwright/*.png`.
  Тек `state/` і `output/` у проєкті немає.
- **D-06 · Машина станів явна: `pipeline/states.py` тримає `StrEnum` і
  словник дозволених переходів** (це дані, не логіка; бібліотека не потрібна).
  Перехід поза словником · `StateError`; екран «Прогін» показує кожен перехід
  із причиною з таблиці `transitions`.
- **D-07 · Веб · FastAPI + Jinja2 + vanilla JS + SSE (`sse-starlette`),
  форми · `python-multipart`.** Без фронтенд-фреймворка й збірки. Сервер слухає
  лише `127.0.0.1`, відкидає чужий `Host`, `Origin` і `Sec-Fetch-Site`; дії ·
  лише POST з реєстру `web/screens/*` (модуль екрана експортує `SCREEN` і `ACTIONS`, результат дії · `WebState.results[name]`, 303 на екран). `base.html` має `referrer same-origin`: з `no-referrer` Chrome шле `Origin: null`, і кожен POST дає 403 (DEFECTS #1). Ключа доступу в адресі немає. Порт
  типово `7660`: `7654` зайнятий сторінкою PHP-попередника (виявлено 2026-09-25).
- **D-08 · Автотестів немає** (D-00b). `bdo gate` · статика за секунди:
  секрети, дзеркала й посилання в docs, `ruff`, правила проєкту, `mypy`.
- **D-09 · Типи · `mypy --strict` на `src/`; лінт і формат · `ruff`.**
  `# type: ignore` дозволений лише з кодом помилки і коментарем чому.
- **D-10 · Логи · JSON-рядки через stdlib `logging` з фільтром редагування
  секретів (`logging_setup.py`) у `.bdo/web.log`.** Значення `*_API_KEY`,
  `X-API-Key`, `Authorization` замінюються на `***` до запису.

## Моделі й транспорти

- **D-11 · Два транспорти через офіційні SDK: `ollama` (`ollama.AsyncClient.chat`,
  `stream=True`, `format` = схема, `think` явно) і `openai`
  (`openai.AsyncOpenAI.chat.completions.create`, `stream=True`,
  `response_format={"type":"json_schema",…,"strict":true}`).** oMLX, OmniRoute і
  хмарні провайдери йдуть через `openai` з `base_url`. Параметри перевірені в
  SDK 2026-09-25: `ollama 0.6.2` (`think: bool | "low"|"medium"|"high"`,
  `message.thinking` у чанку), `openai 3.19.2` (`reasoning_effort`, `extra_body`;
  роздуми · додаткове поле дельти `reasoning_content` або `reasoning` у
  `delta.model_extra`).
- **D-12 · Замінено D-43. Віддалений провайдер вмикає лише `BDO_ALLOW_REMOTE=1` у `.env`.**
  Провайдер із `remote: true` без цього прапорця дає відмову
  `remote_not_allowed` ще до запиту; екран «Моделі» показує її словами.
- **D-13 · Жодних стель генерації.** `num_predict`, `max_tokens` не
  передаються. Зациклення ловить `RepeatWatch` за повторами фрагментів у стрімі;
  таймаут ролі · `timeout_seconds` із `config/roles.json` (1500 с).
- **D-14 · Доповнено D-45. `think` у `config/roles.json` є початковим бажанням ролі.** Стартово `true` для всіх ролей (власник, 2026-09-29, P37: роздуми важливіші для якості перекладу; збережений вибір на `/models` сильніший). Раніше · `false` для всіх, крім `translation-judge`, `translation-repair`, `translation-smoke`, з підставою, що в попередника байтів роздумів утричі більше за відповідь.
- **D-15 · Кожен виклик моделі · рядок у таблиці `calls`** з полями
  попередника (`role, model, provider, batch_id, ms, in_tokens, out_tokens,
  thinking_bytes, think, state, error, attempt, rows, json_salvaged,
  answer_loop_detected`) плюс `request_json` (системний промпт, payload,
  схема, параметри), `content`, `thinking`, `parsed_json`, `replay_of`.
- **D-16 · Replay є функцією першого класу.** Кнопка «Повторити» на екрані
  «Виклик» повторює роль на збереженому `request_json` без API (можна змінити
  модель, провайдер, `think`) і показує обидві відповіді поруч.
- **D-17 · Відмови транспорту · закритий перелік** (`model/transport.py`,
  `FailureReason`): `model_unreachable`, `model_error`, `upstream_unavailable`,
  `rate_limited`, `truncated`, `context_overflow`, `empty_content`,
  `thinking_loop`, `answer_loop`, `not_json`, `schema_mismatch`,
  `stream_incomplete`, `timeout`, `provider_key_missing`, `unknown_provider`,
  `missing_model`, `model_locked`, `remote_not_allowed`. Нова причина · лише через цей enum; `remote_not_allowed` вилучено рішенням D-43.

## Конвеєр

- **D-18 · `identity_hash` не перетинає межу `model/caller.py`.** `RowAlias`
  підміняє його на `id` `r1…rN` у payload і в схемі (enum), відновлює після
  відповіді. Промпти називають поле `id` і ніколи `identity_hash`.
- **D-19 · Порядок кроків пачки** (`pipeline/states.py`):
  `selected → memory_checked → terminology_done → worker_done → checks_done →
  qa_done → healing → judge_done → names_done → validated → committing →
  committed`; побічні: `failed_terminal`, `paused`. P05 вмикає
  `selected → memory_checked → worker_done → checks_done → qa_done → validated
  → dry_run_done`; P06 додає `terminology_done`, `healing`, `judge_done`,
  `names_done`; P07 додає `committing → committed`.
- **D-20 · Маршрути рядка** (`pipeline/routing.py`): чистий і `PASS` → запис у
  канал прогону; механічний дефект або `REJECT`, не вилікуваний за
  `heal_max_attempts` (3) → `moderation` (канал `proposal`, якщо дозволений
  ключу, інакше `deferred`); збій транспорту чи оточення → `deferred`; відмова
  API з `retryable: true` → `deferred`; інша відмова API → `quarantine`.
- **D-21 · Режим прогону · конфігурація `config/modes.json`**, не промпт:
  `patch`, `refresh` (актуалізація ШІ, до 2026-09-30 · `improve`), `manual`, `proposals`. Розходження режимів неможливе за
  побудовою.
- **D-22 · Розмір пачки · вибір власника в межах `GET /me → batch.max_items`;
  default 50.** Механіку перевіряють у браузері на 5 рядках, поведінку моделі
  міряють на 50.
- **D-23 · Кеш термінології на сесію** (таблиця `term_cache`): один resolve на
  `canonical_source`, не на пачку.
- **D-24 · Паралелізм · `max_parallel_batches` у `config/modes.json`, default
  1.** Вмикається лише після заміру в P08.
- **D-25 · Статистика · екран «Статистика»** рахує з SQLite: час за роллю,
  частку пачок із repair, частку `REJECT` від QA, які скасував суддя, кількість
  відкладених і карантинних рядків.
- **D-26 · Запис лише після `POST /translations/validate` тим самим каналом,
  з `Idempotency-Key` за вмістом** (`bdo-` + перші 48 hex sha256 від JSON `{v:1, environment, channel, batch_id, items: [{identity_hash, source_hash, text_sha256}] за identity_hash}`: повтор тієї самої пачки дає той самий ключ; частини понад 50 · `-1`, `-2`; повтор після лікування розмітки · `-markup`). Тіло запису · як у `$OLD/lib/Api/WritePayload.php`
  (read-only), `prompt_version` · `bdo-py-v1`.
- **D-27 · PROD захищений кодом** (замінено D-53): запис у PROD вимагає `BDO_ENV=PROD` І
  непорожнього `BDO_PROD_CONFIRM_CODE` у `.env` І введення того самого коду у
  формі «Старт». Агент PROD-запис не виконує; перевіряє лише видиму відмову.
- **D-28 · Глосарій не пишеться в v1.** Ролі `translation-glossary` немає;
  `POST /glossary/proposals` не викликається. Терміни в проді можуть бути
  неактуальні (рішення власника 2026-09-25), тому термінолог і `names` · P06.
