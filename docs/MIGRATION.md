# Перехід з PHP-попередника

Цей документ допомагає власнику перенести налаштування з PHP-попередника.
Значення ключів і адрес API сюди не копіюються. Сесії та локальна історія
попередника сюди не переносяться (його локальної копії більше немає);
переклади, модерація й глосарій
зберігаються на сервері й не потребують перенесення.

## `.env`: попередник → цей проєкт

| змінна попередника | тут | примітка |
|---|---|---|
| `BDO_ENV` | `BDO_ENV` | Та сама назва; для роботи з розробницьким середовищем задайте `DEV`. |
| `BDO_API_KEY_PROD` | `BDO_API_KEY_PROD` | Та сама назва; секрет зберігайте тільки в `.env`. |
| `BDO_API_KEY_DEV` | `BDO_API_KEY_DEV` | Та сама назва; секрет зберігайте тільки в `.env`. |
| `BDO_API_BASE_PROD` | `BDO_API_BASE_PROD` | Та сама назва. |
| `OPENCODE_API_KEY` | `OPENCODE_API_KEY` | Та сама назва; потрібен для OpenCode Go. |
| `OMNIROUTE_URL` | `OPENAI_COMPAT_ENDPOINT` | URL сумісного з OpenAI джерела моделей. |
| `OMNIROUTE_API_KEY` | `OPENAI_COMPAT_API_KEY` | Ключ сумісного з OpenAI джерела; зберігайте тільки в `.env`. |
| `OLLAMA_URL` | `OLLAMA_ENDPOINT` | Адреса Ollama. |
| `BDO_RUN_MAX_BATCHES` | поле «пачок» на «почати прогін» | Ліміт задається для окремого запуску у вебінтерфейсі. |
| `BDO_JUDGE_MIN_CONFIDENCE` | немає | Поріг судді — 65 у `pipeline/judge.py`; налаштування через `.env` немає. |
| `BDO_CHILD_RETRY_WINDOW_SECONDS` | немає | У клієнті API діє фіксоване вікно повторів `RETRY_WINDOW_SECONDS = 570`; змінної середовища немає. |
| `BDO_CHILD_RETRY_TOTAL_SECONDS` | немає | Окремого загального ліміту повторів немає; використовується `RETRY_WINDOW_SECONDS = 570`. |
| `BDO_AUTO_CLEAN` | немає | Історію власник прибирає вручну кнопкою на «Сесії роботи». |
| `BDO_KEEP_DAYS` | немає | Автоматичного очищення за віком немає; історію власник прибирає вручну на «Сесії роботи». |
| `BDO_TERM_NOTES_*` | немає | Функції нотаток термінів відкладені в BACKLOG. |
| `BDO_CONCEPTS_*` | немає | Функції концептів відкладені в BACKLOG. |
| `BDO_SHARED_EXAMPLES` | немає | Приклади беруться з `related_rows` у контексті рядків (`/rows/context`); окремого перемикача середовища немає. |
| `BDO_EXAMPLES_BUDGET` | немає | Приклади з контексту обмежує код формування payload; змінної середовища немає. |
| `BDO_API_TARGET` | не потрібна | Ціль визначає `BDO_ENV` разом із відповідними `BDO_API_BASE_*` та `BDO_API_KEY_*`. |
| `HUB_API_BASE_*` | не потрібна | У цьому проєкті адресу задають `BDO_API_BASE_DEV` і `BDO_API_BASE_PROD`. |
| `HUB_API_KEY_*` | не потрібна | У цьому проєкті ключ задають `BDO_API_KEY_DEV` і `BDO_API_KEY_PROD`. |
| `TRANSLATE_PROJECT_ROOT` | не потрібна | Проєкт працює з кореня репозиторію; окремий шлях не налаштовується. |
| — | `BDO_API_BASE_DEV` | Нова змінна; адреса API розробницького середовища. |
| — | `BDO_PROD_CONFIRM_CODE` | Прибрано (D-53): коду PROD більше немає. |
| — | `BDO_WEB_PORT` | Нова змінна; порт локальної сторінки, стандартно `7660`. |
| — | `OMLX_ENDPOINT` | Нова змінна для локального провайдера oMLX. |
| — | `/models` | Тут власник обирає активну модель і кнопками налаштовує адреси та ключі провайдерів; `.env` руками не редагується. |

Перевірте назви змінних у `.env.example`. Сам файл `.env` не переноситься
автоматично: власник заповнює його окремо й не додає до Git.

## Що не переноситься

Сесії, журнали й `state/**` попередника не переносяться: його локальної копії більше немає.
Переклади, модерація й глосарій зберігаються на сервері, тому переносити їх
не потрібно.

## Перший прогін після переходу

- [ ] Власник заповнює `.env` за таблицею вище; секрети лишаються тільки в `.env`.
- [ ] Агент піднімає сторінку й робить тестовий прогін без запису на DEV.
- [ ] Власник обирає модель на «Моделі» і, якщо модель локальна, сам робить тестовий прогін без запису на ній.
- [ ] Власник робить перший запис у PROD на 5 рядків через «почати прогін» (перед цим · перехід на PROD у картці «Куди пишемо»).
- [ ] Записані рядки видно на сайті, а «сесії роботи» показують `у шар` = 5.
- [x] Попередника закрито: власник прибрав його локальну копію (2026-10-09).
