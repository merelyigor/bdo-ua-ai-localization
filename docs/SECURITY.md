# Безпека

Репозиторій публічний (D-50): кожен tracked-файл, повідомлення коміту й знімок
читає будь-хто, а видалення значення новим комітом не прибирає його з історії.

## Де живуть чутливі значення

- Ключі API, токени, паролі, приватні URL · лише в локальному `.env` під
  `.gitignore`. У git · лише `.env.example` із порожніми значеннями.
- Не вставляти реальні значення в код, приклади, промпти, коміти, звіти,
  знімки екрана.

## Що є чутливим

- Ключі, токени, cookies, приватні ключі, паролі та їхні хеші.
- Приватні URL і хости, дампи БД, повні відповіді API, файл `.bdo/bdo.sqlite`.
- Персональні дані: e-mail (крім `…@users.noreply.github.com`), домашні
  абсолютні шляхи (`/Users/<імʼя>/`, `/home/<імʼя>/`, `C:\Users\…`), імена й
  облікові записи людей, внутрішні хости й IP. Шлях пишеться відносно кореня.

## Що не є секретом

`identity_hash`, `source_hash`, `call_id` · технічні ідентифікатори. Їх можна
показувати на екрані й передавати в мінімальному payload, але це не дозвіл
публікувати `.bdo/`.

## Локальні приватні дані

Уся локальна інформація · у `.bdo/` під `.gitignore` (D-05a): `bdo.sqlite`
(сесії, пачки, рядки, виклики з запитом і відповіддю, вироки, записи, черги),
`web.log`, `playwright/*.png`. Не комітити, не додавати до звітів, не
передавати віддаленим моделям. Видалення `.bdo/` або записів у ній · лише за
окремим дозволом власника.

## Віддалені моделі

Активну модель власник обирає на `/models`; окремого прапорця віддаленого
доступу немає (D-43). Ключі джерел налаштовуються лише там і лише зі списку
D-44. Віддаленій моделі йде лише payload ролі; ключі, `.env`, `.bdo/` · ніколи.

## Механічні controls

1. `.gitignore` не пускає `.env`, `.bdo/`, `.venv/` у staging.
2. `uv run bdo gate secrets` сканує tracked-файли на патерни ключів, домашні
   шляхи й e-mail і не друкує знайдене значення; hook `commit-msg` так само
   перевіряє повідомлення коміту, `pre-push` запускає `gitleaks`.
3. Логи проходять `RedactSecrets` до запису (`logging_setup.py`).
4. Екран «Стан» показує лише «ключ · задано/відсутній», ніколи значення.

`--no-verify` не є способом виправлення. Хибне спрацювання виправляється
зміною тексту, а не послабленням патерну.

## Якщо секрет витік

1. Зупинити роботу й не повторювати значення в чаті.
2. Повідомити власника: тип credential і місце, без значення.
3. Власник відкликає або перегенеровує ключ у джерелі.
4. Переписування історії git · лише окремим рішенням власника.
