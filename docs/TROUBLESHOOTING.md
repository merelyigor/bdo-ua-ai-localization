# Що робити, коли зламалося

Симптом → причина → дія. Документ для власника й агента, коли прогін
зупинився, рядок не дійшов до запису або API відмовив.

Схема таблиць і станів · [`ARCHITECTURE.md`](ARCHITECTURE.md).
Експлуатація · [`OPERATIONS.md`](OPERATIONS.md).
Коди помилок API · [`API.md`](API.md).

## Як читати симптом

Чотири кроки, від стану пачки до виклику. Усе це таблиці SQLite, їх видно на
екранах і в базі.

1. **Стан пачки** · таблиця `batches`, поле `state`. Значення станів ·
   `src/bdo_translate/pipeline/states.py`:

   | Стан | Що означає |
   |---|---|
   | `selected` | рядки вибрано |
   | `memory_checked` | перевірено памʼять перекладів |
   | `terminology_done` | терміни готові |
   | `worker_done` | переклад готовий |
   | `checks_done` | механічні перевірки пройдено |
   | `qa_done` | контроль якості готовий |
   | `healing` | ремонт дефектів |
   | `judge_done` | суддя вирішив |
   | `names_done` | назви готові |
   | `validated` | перевірено сервером |
   | `committing` | записується |
   | `committed` | записано |
   | `dry_run_done` | тестовий прогін завершено, без запису |
   | `paused` | на паузі власника |
   | `failed_terminal` | зупинено без відновлення |

   Причина · поле `batches.reason`. Статус сесії · таблиця `sessions`,
   поля `status` і `stop_reason`.

2. **Причина в переходах** · таблиця `transitions`: `from_state`, `to_state`,
   `reason`, `at`. Це точний лог шляху пачки: який крок і з якою причиною
   привів у поточний стан.

3. **Дефекти рядка** · таблиця `verdicts`: `identity_hash`, `source`, `status`,
   `code`, `issue`, `fix`. Поле `source` каже, хто виніс вердикт:
   `mechanical` · механічна перевірка, `qa` · контроль якості,
   `judge` · суддя, `api_validate` · перевірка сайту, `api_write` · відмова
   запису. Два значення приходять не з конвеєра, а з екрана «моделі»:
   `probe` · перевірка моделі перед вибором, `catalog` · звірка каталогу
   джерела. Суддя (`judge`) заповнює `issue` причиною, але `fix` лишається
   порожнім · він не переписує текст.

4. **Виклик моделі** · таблиця `calls`: `role`, `provider`, `model`, `state`,
   `error`, `attempt`, `ms`, `request_json`, `content`, `thinking`. Тут видно
   запит, роздуми й відповідь моделі. На екрані «виклики» (`/calls`) вони
   відкриваються детально, а «Повторити» повторює роль на збереженому payload.

Механічна перевірка вердикту йде перед модельними: механічний дефект не
перекривається вироком моделі.

## Прогін зупинився

Три стани, які означають «прогін не дійшов до кінця». Два — стани пачки
(`batches.state`), третій — стан сесії (`sessions.status`).

| Стан | Де лежить | Причина | Що робити |
|---|---|---|---|
| `failed_terminal` | `batches.state` | пачка не може йти далі: відмова моделі, помилка API, зупинка через квоту | прочитайте `batches.reason` і `sessions.stop_reason`; якщо рядки пішли в `deferred`, їх треба перезапустити вручну (див. нижче) |
| `paused` | `batches.state` | власник натиснув «пауза»; сесія призупинена, точка відновлення збережена | натисніть «продовжити» на екрані «прогін»; або завершіть сесію кнопкою «видалити сесію» |
| `interrupted` | `sessions.status` | сервер перезапустили або зупинили під час прогону (статус ставить `repo.interrupt_running()` при старті процесу) | починайте новий прогін; недозаписані рядки лишаться в `deferred`. Стан пачки при цьому не змінюється · він лишається тим, у якому був |

Сесія зі статусом `stopped` · зупинена власником (кнопка «зупинити») або
зупинена через квоту. Кнопка «зупинити» ставить лише прапорець: сесія
завершується **після поточної пачки**, тож статус змінюється не миттєво.

Відкладені рядки: звичайний новий прогін без перемикача «перекласти все»
пропускає всі identity hash із `deferred` (`repo.deferred_hashes()`). Якщо
сесія завершилася з «вибірка порожня», а на екрані видно
`run-all-deferred-hint`, це очікувана межа звичайного відбору, а не збій
перекладу. Для активної черги ввімкніть «перекласти все» або натисніть
«повторити відкладені» на невдалій чи порожній сесії. Кнопка працює в
активному середовищі й з тим самим режимом джерела, що й вибрана сесія; вона
охоплює тимчасові відмови моделі та `missing_item`. Інші причини треба
розібрати окремо. Не знімайте мітку вручну в базі.

Автоматичний повтор у режимі пропозицій (`proposals`) — окремий шлях: конвеєр
добирає відкладені рядки, відкладені **лише** через транспортний зрив
(`ROW_FAILURES` у `model/transport.py`). Ручна кнопка також може повторити
`missing_item`; для такого повтору в режимі пропозицій береться актуальний
текст пропозиції API.

## Рядок у `deferred` або `quarantine`

| | `deferred` | `quarantine` |
|---|---|---|
| Що це | рядок лишився на повтор | рядок із проблемою, яку конвеєр не розвʼязав сам |
| Причини | збій мережі, тимчасова відмова API, ліміт квоти, зупинка пачки | відмова API без можливості повтору, невідомий статус запису, невиправна розмітка |
| Повертається сам | у режимі пропозицій · так, якщо причина транспортна; в інших режимах · ні | ні, треба розібрати вручну |
| Що робити | перевірити причину; для `_RETRY_DEFER_REASONS` відкрити невдалу або порожню сесію того самого середовища й режиму та натиснути «повторити відкладені»; інші причини розібрати окремо | розібрати відмову, поправити переклад або промпт, за потреби записати вручну |

Обидва списки видно на екрані «карантин і запис» (`/queue`) у розділах
«Відкладені» й «Карантин»; у базі це таблиці `deferred` і `quarantine`.
Причина завжди в полі `reason`.

Кнопка «Архівувати карантин» позначає записи як `archived`, а не видаляє
їх ([`COMMITS.md`](COMMITS.md)).

## Відмова API

Повний перелік кодів і підказок · [`API.md`](API.md) та
`src/bdo_translate/api/errors.py` (`ERROR_HINTS`). Ключові:

| Код | Що це | Що робити |
|---|---|---|
| `unauthorized` | ключ API не прийнято | перевірте ключ на екрані «підключення»; ключ починається з `bdo_` |
| `forbidden` | ключ не має права на цю дію | потрібен ключ із відповідною роллю; для прямого машинного запису · `admin`/`super_admin` |
| `daily_row_quota_exceeded` | денна квота рядків вичерпана | прогін зупиняється, рядки йдуть у `deferred`; повтор після опівночі за київським часом ([`OPERATIONS.md`](OPERATIONS.md)) |
| `retry_exhausted` | усі повтори в клієнті вичерпано (вікно 570 с) | перевірте мережу й доступність API, запустіть знову |
| `active_proposal_exists` | у цього автора вже є відкрита пропозиція | трапляється лише при записі пропозиції (`mode=proposal`); для ШІ-шару вибірка ставить `exclude_proposed=1` |
| `stale_source` | джерело змінилось після перекладу | перечитайте рядок і перекладіть заново; код не повторюється автоматично |
| `markup_functional_breakage` | зламані обовʼязкові токени розмітки | скопіюйте всі токени `must_preserve` дослівно |
| `save_failed` | сервер не зберіг рядок | найчастіше зайвий `\n`, якого немає в оригіналі |

Розбір конверта й підказки · `api/client.py:parse_envelope`.

## Відмова моделі

Причини відмови транспорту · закритий перелік `FailureReason` у
`src/bdo_translate/model/transport.py` (D-17). Їх 17; нижче вони поділені на
три групи за дією конвеєра.

**Зупинка — перевірте налаштування, повтор не допоможе:**

Ці шість причин не входять у жоден із наборів коду (`WAITABLE`, `LOOPS`,
`ROW_FAILURES`), тож конвеєр на них не чекає й не переносить рядки в
`deferred`: сесія зупиняється одразу (`runner._fail_session`).

| Причина | Що перевірити |
|---|---|
| `provider_key_missing` | ключ джерела не заданий; задайте на екрані «підключення» |
| `unknown_provider` | назву провайдера не розпізнано |
| `missing_model` | моделі немає в каталозі джерела; перевірте каталог на екрані «моделі» |
| `model_locked` | модель замкнена; оберіть іншу на екрані «моделі» |
| `model_unreachable` | джерело моделі не відповідає |
| `model_error` | помилка на боці джерела моделі |

**Очікування — конвеєр сам чекає й повторює:**

| Причина | Що робить |
|---|---|
| `rate_limited` | джерело обмежило темп; витримується `Retry-After` або експоненційна пауза |
| `upstream_unavailable` | джерело тимчасово недоступне; те саме очікування |

**Зрив відповіді — пачка йде в `failed_terminal`, рядки в `deferred`:**

| Причина | Що це |
|---|---|
| `truncated` | відповідь обрізана |
| `not_json` | відповідь не JSON |
| `schema_mismatch` | відповідь не за схемою ролі |
| `answer_loop` | модель зациклилася у відповіді |
| `thinking_loop` | модель зациклилася в роздумах |
| `empty_content` | порожня відповідь |
| `stream_incomplete` | потік обірвався |
| `timeout` | час вийшов |
| `context_overflow` | не вмістилося у вікно контексту |

Зациклення й обрив потоку дають один додатковий повтор усередині виклику
(`model/caller.py`); решта повертається одразу.

Точно: додатковий повтор мають лише чотири причини — `stream_incomplete` і
`timeout` (лічильник `transport_retries`), `answer_loop` і `thinking_loop`
(лічильник `loop_retries`). Решта причин із таблиці «Зрив відповіді»
повертається з виклику одразу.

## Прогін зупинився на повторі

Повторювана відмова однієї ролі зупиняє всю сесію з причиною
**«винна модель, а не рядки»**. Так виглядає збій моделі або джерела, а не
поганих рядків:

- у `sessions.stop_reason` · рядок «винна модель, а не рядки: `<роль>` `<причина>`»;
- у журналі · та сама причина; у `calls` · `state: failed`, `error` із кодом
  відмови;
- у базі · `batches.reason` і `transitions.reason` з кодом відмови.

Що робити:

1. Подивіться, яка роль відмовляється (`translation-worker`,
   `translation-terminology`, `translation-qa`, `translation-repair`,
   `translation-judge`, `translation-names`).
2. Відкрийте останні виклики цієї ролі на екрані «виклики» й прочитайте
   `request_json` та `content` — видно, що саме модель віддала.
3. Перевірте модель: змініть активну модель або режим роздумів на екрані
   «моделі»; перевірте досяжність джерела.
4. Прогін на пачці меншого розміру, щоб побачити, чи справа в конкретному
   рядку.
5. Натисніть «повторити відкладені». Почніть із малої пачки (від 5 рядків).

Кнопка показує кількість придатних рядків з черги активного середовища й того
самого режиму джерела, а не лише з поточної сесії. Вона повторює тимчасові
відмови моделі та `missing_item` (worker не повернув переклад). Відмови API,
механічні дефекти й рішення QA або судді потребують окремого розбору й не
входять до ручного повтору. Якщо запит рядка за `identity_hash` повертає 404,
рядок позначається причиною `row_not_found` і більше не пропонується для повтору.
Якщо режим пропозицій більше не має відкритої пропозиції, причиною стає
`proposal_not_found`; такий рядок також перестає бути придатним до повтору.

Повтор одного й того самого виклику на тих самих даних не змінить результат:
спершу правте модель, промпт або пачку.

## Пачка не має вибраних рядків

На екрані «прогін» відкрийте потрібну пачку з історії сесій або рядків; блок
`run-fetch-diagnostic` («Вибірка рядків») показує збережені агрегати для її
`batch_id`, якщо це звичайне читання рядків або ручний повтор. Під час активного
читання блок показує останній збережений стан і оновиться під час наступного
оновлення екрана. Звичайний режим переліку рахує
отримані сторінки API; ручний повтор робить запити за окремими
`identity_hash`, тож його діагностику не слід читати як кількість сторінок.

Для пачок, створених до встановлення діагностики, ці дані заднім числом не
відновити: у старій історії лишається лише загальна причина зупинки. Нові
агрегати зʼявляться після оновлення застосунку в наступних прогонах.

- `API повернув 0 рядків` у звичайному режимі означає, що відповідь переліку
  була порожня. Перевірте фільтр/запит режиму й наявність відповідних рядків у
  джерелі API.
- Якщо API повернув рядки, але вибрано 0, подивіться лічильники пропуску:
  дублікати, `deferred`, рядки попередніх пачок і механічно неперекладні рядки.
  Якщо `порожнє джерело` більше нуля, перевірте дані рядків у джерелі API.
- Якщо звичайний перелік API повідомив про наступну сторінку без курсора, екран
  позначить це; перевірте пагінацію/відповідь API перед повтором.

Зменшення розміру пачки не виправляє порожню відповідь API або рядки, відсіяні
фільтрами. Спершу усуньте причину, яку показують агрегати; потім запустіть нову
пачку.

## Квота й ліміти

Денна квота рядків і ліміт запитів на хвилину приходять із ключа:
`GET /me` → `limits` (`rows_per_day`, `rows_remaining_today`,
`requests_per_minute`, `quota_resets_at`). Залишок видно на екрані «API» і
на екрані «моделі» (ліміти підписки Go).

Квота вичерпана · прогін зупиняється, рядки йдуть у `deferred`, повтор — після
опівночі за київським часом. Докладно · [`OPERATIONS.md`](OPERATIONS.md),
розділ «Квота».

Ліміт запитів (`rate_limited`) не зупиняє прогін: клієнт чекає й повторює
сам. Якщо повторів вичерпано, приходить `retry_exhausted`.
