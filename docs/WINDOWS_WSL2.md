# Windows через WSL2

Toolkit на Windows виконується ТІЛЬКИ всередині WSL2: `./bdo`, PHP і `jq`
живуть у Linux. Native PowerShell, Git Bash і PHP, встановлений через `winget`,
не є runtime цього набору.

Причина не в смаку. Скрипти набору покладаються на bash, `mktemp`, права
файлів і поведінку `sed`/`grep`, які на Windows інші. Другий flow під
PowerShell означав би другу реалізацію тих самих перевірок · тобто два місця,
де може розійтися одне правило.

## 1. Одноразове встановлення

Ці команди потрібні лише для первинного налаштування або діагностики. У
щоденній роботі власник змінює тільки локальний `.env` і працює через меню
`./bdo`.

У PowerShell від адміністратора встановіть WSL2, якщо його ще немає:

```powershell
wsl --install -d Ubuntu-24.04
```

Після перезавантаження відкрийте Ubuntu і виконуйте решту команд лише там:

```bash
sudo apt update
sudo apt install -y git php-cli jq curl
php -v
```

Потрібен PHP 8.3+. Далі решту доставляє сам набір: `./bdo platform` друкує,
чого бракує, а `./bdo platform --fix` ставить це через apt.

Необовʼязковий `shellcheck` потрібен лише для `./bdo gate shell`. Без нього
прогін працює, а preflight дає WARN, а не помилку.

## 2. Клон і ключ

Репозиторій клонуйте в Linux filesystem, не в `/mnt/c`: на `/mnt/c` файлові
операції повільні, а права поводяться інакше.

```bash
mkdir -p ~/GitHub
cd ~/GitHub
git clone https://github.com/merelyigor/bdo-ua-ai-localization.git
cd bdo-ua-ai-localization
cp .env.example .env
```

У приватному `.env` задайте `BDO_ENV` і ключ відповідного середовища. Не
публікуйте `.env` і не вставляйте ключ у чат.

## 3. Локальні моделі

Ollama ставиться в тому ж WSL або на хості. Якщо Ollama працює на Windows-хості,
а набір · у WSL, вкажіть адресу явно:

```bash
# у .env
OLLAMA_URL=http://host.docker.internal:11434
```

Перевірка одним кроком:

```bash
./bdo runtime
```

Вона робить справжній виклик `cli/model/client.php` · той самий файл, який
працює на пачці, · і падає з причиною, якщо endpoint недоступний, модель не
завантажена або схема не тримається.

## 4. Перевірка розкладки

```bash
./bdo gate preflight
```

Правильний результат містить `Платформа: Windows/WSL2`. Якщо набір бачить
Windows, PowerShell або пропонує `winget install PHP`, відкрито не той runtime:
закрийте його й відкрийте WSL-копію проєкту.

## 5. Запуск

```bash
./bdo web
```

Команда друкує посилання виду `http://127.0.0.1:7654/?t=…`. Відкривати його
можна в звичайному браузері на самому Windows: WSL2 пробрасує loopback, тому
`127.0.0.1` у Windows-браузері бачить сервер, що працює всередині WSL. Якщо
браузер не відкрився сам, скопіюй посилання руками або постав `wslu`
(`sudo apt install wslu`) · тоді працює `wslview`.

Перевірити готовність саме цієї частини:

```bash
./bdo platform
```

Рядок `Браузерний інтерфейс: сервер піднімається, воркерів N` означає, що
сторінка запуститься й потік токенів працюватиме. `воркерів 1` · сторінка
працюватиме, але потік відкотиться на опитування (це нормально, просто
повільніше оновлюється).

Без браузера все так само працює в терміналі WSL:

```bash
./bdo
```

Це вікно-монітор: стан, журнал ролей, продовження незавершеної пачки й
запуск прогону без браузера. Жодного додаткового застосунку не потрібно.
