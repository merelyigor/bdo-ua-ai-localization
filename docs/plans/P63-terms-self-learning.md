## Навіщо

Глосарій може бути застарілим, а власник хоче мінімум ручної роботи. P62
збирає сигнали «модель упевнено обирає інший відповідник, ніж порада»
(`term_signal`). Цей план робить із сигналів дію:
- стійке відхилення від ПОРАДИ · автоматична пропозиція терміна на сайт з доказами;
- суперечка з ЗАКОНОМ (людським терміном) · ніколи не автоматично, лише рядок на екрані конфліктів для власника;
- та сама англійська назва має той самий переклад по корпусу · механічна перевірка однаковості.

Людина лишається лише на короткому списку конфліктів, який програма складає сама.

## Goal

- Екран «конфлікти термінів»: назва, що каже глосарій, що обирає модель, скільки рядків і прогонів, приклади; дія власника · «прийняти варіант моделі як пропозицію» або «лишити глосарій».
- Стійкі відхилення від поради йдуть сайту пропозицією без участі власника (поріг нижче).
- Розбіжний переклад тієї самої назви в корпусі видно й лікується конвеєром.

## Definition of Done

- [ ] Контракт сайту на пропозицію ВІДПОВІДНИКА терміна (не лише опису) отримано й записано тут; чинний `POST /glossary/proposals` (`docs/API.md`) приймає опис (`gist`, `definition`), а не новий український відповідник · без контракту крок 1.3 `blocked`.
- [ ] Агрегація `term_signal` (P62 1.5): група за (`canonical_source`, фактичний відповідник); поріг стійкості · ≥ 5 різних рядків і ≥ 2 різні прогони (сесії), частка ≥ 80 % серед вжитків цієї назви; поріг · у `config/` (не в коді).
- [ ] Екран конфліктів (новий або блок `/quality`), дії з реєстру екрана (D-07).
- [ ] Автопропозиція для поради за порогом · не частіше одного разу на пару (назва, відповідник); відповідь сайту видно на екрані.
- [ ] Перевірка однаковості: для назви з `glossary/match` (P61) у рядку · переклад порівнюється з найчастішим перекладом цієї назви в чинному ШІ- і ручному шарі корпусу; розбіжність · порада ремонту, не блок.
- [ ] Звірка на DEV (запис на DEV · стоячий дозвіл власника 2026-10-02; пропозиції на сайт DEV · теж DEV); знімки `P63-*`; gate 0.
- [ ] План видалено на закритті (D-59).

## Non-goals

- Автоматична зміна людського терміна (закону). Ніколи.
- Зміна глосарія напряму (агентське API цього навмисно не вміє: `POST /glossary` · адмінка).
- Опис понять гри (`GET /glossary/concepts`) · рядок «Відкладене» реєстру планів.

## Constraints

- **СТОП: терміни на паузі** · як у P62: лише після зняття паузи власником.
- Залежить від P62 (рівні довіри, `term_signal`). Без закритого P62 · не починати.
- На PROD пропозиції · лише прогонами власника; агент шле пропозиції лише на DEV.
- Безкоштовна віддалена модель отримує лише payload рядків гри.
