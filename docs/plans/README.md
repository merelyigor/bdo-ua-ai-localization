# Плани: реєстр і життєвий цикл

> **Уся черга робіт одним списком · [BACKLOG.md](BACKLOG.md).**
> **Що вже ламалося й чим закрито · [DEFECTS.md](DEFECTS.md).**
> **Підозрілі записи глосарію на перевірку людині · [GLOSSARY_SUSPECTS.md](GLOSSARY_SUSPECTS.md)** (генерує `./bdo suspects`).
> **Що перевіряти після зміни й після прогону · [../CHECKLIST.md](../CHECKLIST.md).**
> Стан усіх трьох одним екраном · `./bdo review`. Реєстр нижче є
> джерелом правди про статус самих планів.

`docs/*.md` описують поточний фактичний стан. `docs/plans/**` описують майбутню,
активну або завершену роботу. План не підміняє довідник, а закритий план не
переписується як новий roadmap.

## Статуси

| Тека | Статус | Значення |
|---|---|---|
| `active/` | у роботі | Реалізація почалася, але Definition of Done ще не виконаний. |
| `backlog/` | не починався | Узгоджений намір без реалізації. |

Теки закритих планів немає: виконаний план ВИДАЛЯЄТЬСЯ. Рішення власника
2026-09-04 · результат закритої роботи живе в коді, тестах і `DEFECTS.md`, а не
в паралельному описі, який доводиться синхронізувати. Залишок закритого плану
переноситься рядком у `BACKLOG.md` разом із вказівником на живий документ.

## Обов'язковий заголовок

```markdown
# Назва плану

- **Статус:** active | backlog
- **Створено:** YYYY-MM-DD
- **Реєстр:** [docs/plans/README.md](../README.md)
```

## Правила ведення

1. Новий план і запис у цьому реєстрі створюються разом.
2. `backlog` переходить в `active` з першою зміною реалізації.
3. `active` закривається (файл видаляється) лише коли кожен пункт підтверджений
   файлом, командою або тестом чи явно переданий рядком у `BACKLOG.md`.
4. Реєстр і `BACKLOG.md` оновлюються разом зі зміною статусу.
5. Формулювання «готово» без доказу не приймається.
6. Добра ідея, яку власник свідомо відклав, потрапляє сюди В МОМЕНТ рішення, а
   не «колись потім». На питання «що варто покращити або додати» відповідь
   починається з цього реєстру й `BACKLOG.md`, і лише потім · з нових пропозицій.
