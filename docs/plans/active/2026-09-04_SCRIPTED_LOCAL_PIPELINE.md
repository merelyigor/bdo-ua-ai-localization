# Скриптовий конвеєр на локальній Ollama · спадкоємець без диригента

- **Статус:** active
- **Створено:** 2026-09-04
- **Реєстр:** [docs/plans/README.md](../README.md)

**Мета:** перекладати без LLM-оркестратора. Порядок кроків задає скрипт, моделі
виконують рівно одну роботу кожна, усе живе в терміналі. Рішення власника
2026-09-04: успадкувати ядро, законсервувати поточний проєкт тегом, гілкою і
zip-архівом, TUI писати чистим bash без залежностей.

## 1. Чому саме оркестрація

Не «OpenCode поганий», а конкретніше: **керування потоком віддане моделі**, і
саме там ламається все. З 45 записаних дефектів прямо через диригента виникли
14: D15 (Task без ролі), D16, D17 (відмова замість підстановки), D20/D21
(runtime-відбиток), D25 (ціль загубилась при стисканні), D30 (звіт замість
кроку), D34 (ціль звузилась до категорії), D35 (здогад замість причини), D36
(вигаданий payload), D38, D39 (сигнал, що додав роботи), D40 (1,96 млн токенів
і зупинка), D45 (2,77 млн токенів і смерть сесії). Ще 174 записи в
`state/prompt-violations.jsonl` · це диригент, що щоразу складав payload сам.

Ціна теж вимірна. За 12 пачок 2026-09-04: усі семеро child разом витратили
≈336 тис. вхідних токенів, а ОДНА сесія диригента · 2 767 379. Тобто на
корисну роботу пішло 11%, решта · переказ станів самому собі.

Головне: **диригент нічого не вирішує вже сьогодні.** `cli/run/run-drive.sh`
віддає готове `{"kind":"child","role":…,"payload_path":…,"response_path":…}`.
Модель лише переносить файл між двома шляхами. Це цикл на сорок рядків.

## 2. Що успадковуємо, що знімаємо

Рішення власника: успадкувати ядро, зняти шар оркестрації.

**Лишається (перевірене, за ним 45 закритих дефектів):**
- `lib/Pipeline/StateMachine.php` · 17 станів і дозволені переходи;
- `lib/Quality/**` · гомогліфи (D23), русизми, чужа писемність, глосарій,
  `VerdictSet::assertCoverage`, `GlossaryExamples` (D24), `GlossarySuspects`;
- `lib/Api/**`, `cli/api/**` · клієнт Agent API, канали запису (D33), retry без
  повтору постійних помилок (D27), потокова пагінація глосарію;
- `lib/Batch/**`, `cli/batch/**`, `cli/quality/**`, `cli/write/**`, `cli/heal/**`;
- `cli/run/run-drive.sh` як **ядро рішень** · що робити далі, вирішує він;
- `tests/**`, `scripts/agent-check.sh` · gates лишаються умовою коміту.

**Знімається:**
- `roles/**` цілком (3679 файлів): плагіни execution-guard, child-contract,
  routing-guard, result-writer, autopilot; чотири primary-промпти; агенти;
  `node_modules`;

- профілі хмарних моделей у `translation-models.json` (session-free, -go,
  -luna, -omniroute) · лишається лише локальний реєстр ролей;
- `cli/audit/model-run.sh` у частині читання бази OpenCode · аудит переходить
  на ВЛАСНИЙ журнал викликів (`cli/audit/response-shape.php` лишається, він
  модель-незалежний);
- `cli/runtime/check-runtime.sh`, `custom-provider-models.php` ·
  оголошення моделей більше нікому не потрібне.

## 3. Архітектура

```
./bdo                      без аргументів · TUI; з аргументами · та сама CLI
  bin/tui.sh               меню, екрани, живий прогрес (bash + ANSI, без залежностей)
  cli/run/run-loop.sh      ДРАЙВЕР: цикл drive -> dispatch -> drive
  cli/model/invoke.sh      виклик Ollama під роль: prompt + schema + payload
  cli/model/registry.php   реєстр ролей: модель, схема, ліміти, температура
  roles/<роль>.md          промпт ролі, звичайний markdown без frontmatter
  roles/<роль>.schema.json схема відповіді
  lib/**                   успадковане ядро
  state/**, output/**      без змін
```

### Драйвер · серце переходу

```
поки не термінальний стан:
    next = ./bdo run drive
    kind=child     -> cli/model/invoke.sh роль payload response; далі
    kind=continue  -> далі (причина в журнал)
    kind=retry     -> backoff за причиною, лічильник спроб з run-drive
    kind=blocked   -> стоп, причина на екран
    kind=complete | goal_complete -> наступна пачка або кінець
```

Жодного рішення моделі. Порядок ролей, ретраї, карантин, фінальна валідація
перед записом (D37) лишаються там, де вже є · у `run-drive.sh`.

### Клієнт Ollama · вимоги з набитих шишок

- `POST /api/chat` з `format` = схема ролі (structured outputs), `think: false`
  (D28: `off` означає «не сказано», а не «вимкнено»);
- `options.num_ctx` береться з `/api/ps` завантаженої моделі, не з `ollama show`
  (D32: повзунок застосунку сильніший за максимум моделі);
- fail closed: порожній `content`, `done_reason != stop`, обрив на стелі ·
  це ПОМИЛКА з причиною, а не «спробуємо ще» (D29);
- кожен виклик пише рядок у `state/model-calls.jsonl`: роль, модель, вхід,
  вихід, мс, вирок форми. Це і є новий аудит замість бази OpenCode.

### Ролі

Ті самі сім: terminology, worker, qa, repair, judge, glossary, smoke. Промпт
лишається самодостатнім `.md` (правило проєкту), але без OpenCode-frontmatter:
модель і схему задає `registry.php`. Рамка «офіційна українська локалізація BDO»
і заборона спиратись на памʼять про російську локалізацію · без змін.

### Режими

Стають КОНФІГУРАЦІЯМИ прогону, а не промптами:

| Режим | Що вибирає | Куди пише |
|---|---|---|
| патч | рядки патчу за фільтром | machine |
| ручний | вузький набір, людина підтверджує | manual |
| пропозиції | той самий конвеєр | proposal |
| покращення-ші | наявні machine-рядки на повторний прохід | machine |

Спільний текст чотирьох промптів більше не може розійтися (`primary-prompt-drift`
стає непотрібним), бо промпту режиму просто немає.

### TUI

1. Головне меню: чотири режими, «Стан», «Журнал», «Глосарій», «Налаштування».
2. Екран вибору: патч і категорія через `./bdo patches`, розмір пачки.
3. Екран прогону: пачка, стан, «крок 4/9», лічильники у шар / модерація /
   карантин, останні пʼять рядків, час на пачку.
4. `Ctrl-C` · зупинка між кроками, стан на диску; продовження з того ж місця.

## 4. Пропускна здатність · чесна цифра

За 12 пачок по 50 рядків усі ролі разом дали ≈112 тис. вихідних токенів, тобто
≈9,4 тис. на пачку. На `qwen3.6:35b-a3b-mtp` (48-52 tok/s) це ≈3-4 хвилини
генерації на пачку плюс обробка вводу · орієнтовно **4-6 хвилин на 50 рядків**,
близько 600 рядків за годину. Патч на 30 тис. рядків · приблизно **50 годин
безперервної роботи**.

Це не вада, а головний аргумент за скрипт: цикл працює вночі без «продовжуй»,
тоді як диригент вимагав людини щопачки й помирав кожні 11 пачок.

## 5. Ризики, названі наперед

- **Суддя на локальній моделі.** Заміряно 2026-08-28: `qwen3.6` QA 0.90/0.90,
  `gemma4:26b` · 0.00/0.00. Отже роль судді прив'язується до конкретної моделі
  в реєстрі, а не до «локальної моделі» взагалі; при недоступності · рядок іде
  до людини, а не судиться абияк.
- **Паралелізм.** Ollama серіалізує запити на одну модель. Дві моделі одночасно
  · це памʼять. План: послідовно, але перекривати мережеві виклики API з
  генерацією.
- **Втрата OpenCode як UI.** Разом із ним зникає зручний перегляд транскриптів.
  Компенсація · власний журнал `state/model-calls.jsonl` і екран «Журнал».
- **Регресія якості.** Поточні цифри (193 рядки в шар зі 200, модерація 3,5%)
  зняті з хмарних маршрутів OmniRoute. На локальній моделі їх треба ПЕРЕМІРЯТИ
  на тих самих пачках, перш ніж оголошувати перехід успішним.

## Definition of Done

Патч перекладається від початку до кінця однією командою з меню, без жодного
«продовжуй», з журналом кожного виклику моделі, і `./bdo gate full` зелений ·
**виконано**.

Показник якості локальної моделі **не заміряний**: спроба виміру впіймала
серверний дефект (D54), через який 60 із 73 карантинних рядків є хибними
відмовами. Тому DoD плану лишається відкритим не через нашу якість, а через
чужий шар · і це різні речі.

Технічна частина переходу (фази 0-5) виконана й зелена.

## Відкриті питання (рішення власника, не блокують фази 0-2)

1. Чи лишається `translation-judge` у конвеєрі на локальній моделі, чи спірні
   рядки одразу йдуть до людини до окремого заміру.
2. Чи потрібен режим «нічна черга»: список патчів, який драйвер бере сам.
3. Чи лишати `./bdo` як імʼя входу (звичка власника) чи дати нове.
