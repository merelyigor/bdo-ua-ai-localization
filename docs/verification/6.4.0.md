# Verification 6.3.10

## Зовнішній `date`

Правило: `BatchNewCommand` бере timestamp через `Bdo\Translate\Cli\LocalTime::stamp()`; тимчасовий subprocess `session.sh ensure` лишається дозволеним seam.

Дослівний sabotage diff:

```diff
--- lib/Cli/Command/Batch/BatchNewCommand.php
+++ lib/Cli/Command/Batch/BatchNewCommand.php
@@
-        // Беремо ту саму системну зону й формат, але без Unix-процесу: PHP має
-        // працювати нативно на Windows, а session.sh лишається тимчасовим seam.
-        $stamp = LocalTime::stamp();
+        exec('date +%Y%m%d_%H%M%S', $stampOutput, $stampCode);
+        $stamp = trim((string) ($stampOutput[0] ?? ''));
+        if ($stampCode !== 0 || $stamp === '') {
+            throw new RuntimeException('Не вдалося отримати час для створення пачки.');
+        }
```

САБОТАЖ: `date` було повернуто у PHP-команду. Регресійний сценарій запускає абсолютний PHP з PATH, де є лише fake `bash`; fake дозволяє тільки `cli/system/session.sh ensure`, а виклик `date` має відмовити.

Команда:

```text
set +e
start=$(date +%s%N)
bash tests/cli-batch-heal-parity.sh > /tmp/batch-parity-sabotage.out 2> /tmp/batch-parity-sabotage.err
code=$?
end=$(date +%s%N)
```

Релевантний вивід:

```text
elapsed_seconds=0.530
exit_code=1
--- stderr ---
FAIL: batch-new залежить від зовнішнього date (code 1): sh: date: command not found
ПОМИЛКА: Не вдалося отримати час для створення пачки.
--- stdout ---
```

САБОТАЖ відновлено повністю. Після відновлення:

```text
bash tests/cli-batch-heal-parity.sh
cli batch/heal parity: 5 команд, routing, stdout/stderr/коди й state files: OK
exit_code=0
```
