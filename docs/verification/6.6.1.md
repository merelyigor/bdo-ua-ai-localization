## Scope

This package changes only the Windows workflow job, the PowerShell smoke, and
the Stage6 process record. Production PHP diff is zero; `cli/**`, `bdo`,
`bdo.bat`, `phpstan.neon`, `DEFECTS.md`, and `docs/ai-workflow/**` are unchanged.

`EnvCommand` is not a positive proof because it invokes `bash` through
`proc_open`. The smoke therefore resolves the absolute `php.exe` first, checks
`PHP_OS_FAMILY=Windows`, then restricts `PATH` to the PHP directory and
`System32`. `Get-Command bash` must find nothing before any positive case.

The synthetic UTF-8 environment is created under `RUNNER_TEMP` with DEV,
legacy target, a dead localhost base, and a dummy key. Inherited
`BDO_API_BASE`, `BDO_API_KEY`, and `BDO_API_ENV` are cleared. No live API is
used.

## Runtime contracts

The smoke runs absolute PHP against `cli/bdo.php`:

- `help`: code 0, empty stderr, root help header and registry line in stdout.
- `run-spec status patch active`: code 0, JSON `ok=true`, `mode=patch`,
  `patch=active`, `domain=null`; stderr announces DEV.
- `env`: expected nonzero in the same sanitized PATH because `bash` is absent;
  this is the negative control, not a positive Windows-native claim.

The positive `run-spec status` path makes no HTTP request; the base is a dead
localhost address and no HTTP stub or live key is used.
